# balances-parser — автозаполнение баланса из инвойсов

Инструмент читает инвойсы поставщиков за поставку и вписывает суммы в файл
**«балансы актуальные»** — в столбец нужного поставщика. Ручная работа
(открыть каждый инвойс → найти сумму → найти столбец → вписать формулу)
сводится к «просмотреть отчёт и добить несколько исключений».

> Стек — **Python** (пакет `pyparser/`). Каркас Spring Boot/Java в репозитории
> не используется. Оригинал баланса никогда не изменяется — создаётся копия.

---

## 1. Что делает

Вход: папка поставки `excel\<дата>\` с подпапками:
- `co` / `ec` / `ke` — инвойсы ферм (Колумбия / Эквадор / Кения);
- `t_common` — фрахтовые AWB (перевозчики);
- `ready *` — готовые файлы (**не трогаем**).

Выход рядом с балансом:
- `..._auto.xlsx` — копия баланса с дописанными суммами;
- `..._auto_report.csv` — что записано / пропущено / на проверку;
- `..._auto_очередь.xlsx` — **редактируемая очередь** нераспознанного.

Правила записи:
- **одна строка на поставщика за поставку**;
- «отгрузка» = формула `=инв1+инв2+...` (суммы отдельных инвойсов);
- «итого» — накопительная формула (пересчитывается Excel-ом сама);
- дата — **самая ранняя** среди инвойсов поставщика;
- запись **после последней заполненной** строки блока;
- повторный запуск **не дублирует** (сверка по дате+формуле).

## 2. Как это работает (конвейер)

```
файлы поставки
  → readers.py    чтение pdf/xls/xlsx в единый вид (+ OCR для сканов)
  → extract.py    поставщик + сумма(ы) + дата + валюта
  → aliases.py    имя из инвойса → столбец баланса
  → balance.py    запись формулой в копию баланса
  → phase2.py     агрегация по поставщику + отчёт + очередь
```

**Распознавание поставщика.** По имени файла (`INV-*` → IMPEX) и по тексту
через справочник алиасов. Фрахтовые перевозчики (PACIFIC/IFC/AIRFLO) ищутся
**только в `t_common`**, чтобы не путать с «карго-агентом» в farm-инвойсах.
Сопоставление устойчиво к склейке слов OCR.

**Сумма.** Уровнями по надёжности: явные метки (`INVOICE TOTAL`, `AMOUNT DUE`,
`TOTAL: USD`, `NET AMOUNT`, `TOTAL EUR`…) → число перед `$` в строке `TOTAL`
(эквадорский формат `1460,00$`) → сумма табличных `TOTALS` (многоинвойсовые
листы) → максимум числа с 2 десятичными. Отсекаются не-денежные «TOTAL»
(боксы/стебли/вес) и суммы в KES.

**Дата.** По метке, по Excel-серийнику рядом с `DATE`, фолбэком — из ячеек.

**Многоинвойсовые файлы.** Напр. `GLOBAL.xlsx` (Flores Mendez) с 11 блоками
`TOTALS` → `=293.5+130.5+...`. Дубли форматов (`GLOBAL.pdf` == `GLOBAL.xlsx`)
отсекаются по имени файла.

**OCR (сканы).** `rapidocr-onnxruntime` + `pypdfium2` (CPU, без внешних
установок). Farm-скан с распознанным поставщиком пишется автоматически.
Фрахтовые AWB (плотная форма, OCR путает Total Prepaid и TRM-курс, даты
искажаются) **не пишутся вслепую** — уходят в очередь со списком USD-кандидатов.

**Пропускаются** (не инвойсы): манифесты/развесовки (`*BXS*`), сводники
(`GLOBAL-FFG, GLOBAL-IA <дата>.xlsx`, `GRD-GGD*.xlsx`), `REPORTE*`, `MANIFEST*`.

## 3. Запуск

### Требования
Python по пути `%LOCALAPPDATA%\Python\pythoncore-3.14-64\python.exe`
(обычный `python` в PATH — сломанный стаб Microsoft Store).
Библиотеки: `openpyxl pdfplumber xlrd rapidocr-onnxruntime pypdfium2 numpy`.

### Шаг 1 — обработать поставку
Двойной клик по **`Обработать баланс.bat`**
или в терминале:
```
python -m pyparser.phase2
```
Само найдёт свежую поставку и свежий баланс в `excel\`. Явно:
```
python -m pyparser.phase2 --folder "excel\07.02" --balance "excel\балансы актульные 0626.xlsx"
```
Результат: `..._auto.xlsx`, `..._auto_report.csv`, `..._auto_очередь.xlsx`.

### Шаг 2 — разобрать очередь (нераспознанное)
Откройте `..._очередь.xlsx`. Жёлтые ячейки — заполнить:
- **Поставщик** — точное имя столбца из баланса;
- **Дата** — `ГГГГ-ММ-ДД`;
- **Суммы** — число или `a+b+c` (для фрахта выберите Total Prepaid из подсказки);
- **Записывать** — поставьте `да`.

Затем **`Дописать очередь.bat`** или:
```
python -m pyparser.review
```
Создаст `..._ready.xlsx` — баланс с дописанными строками из очереди
(агрегируются по поставщику, дубли не пишутся).

### Только распознавание (без записи)
```
python -m pyparser.phase1 --folder "excel\07.02"
```
Печатает таблицу «файл → поставщик → дата → сумма → статус».

## 4. Добавить нового поставщика / изменить столбец

Правьте `pyparser\aliases.py`:
- `FARM_ALIASES` — «фрагмент имени в инвойсе (ВЕРХНИЙ регистр)» → «имя столбца в балансе».
  Ключом может быть имя, email, сайт или **RUC/VAT** (надёжно, когда имени нет в тексте).
- `FREIGHT_ALIASES` — перевозчики (ищутся только в `t_common`).
- `NEW_COLUMNS` — если столбца ещё нет в балансе (создастся в конце листа).
- `FILENAME_RULES` — привязка по имени файла.
- `SKIP_FILE_PATTERNS` — что игнорировать (манифесты/сводники).

Примеры уже настроенных нетривиальных случаев:
- `INV-*` → IMPEX (поле FARM внутри игнорируем);
- файлы «Реализация товаров и услуг» = инвойсы Floralchain → столбец **GREENDEAL**;
- `INVOICE 536647` и др. Airflo B.V. → **AIRFLO** (ключ по VAT `NL813909867B01`);
- сканы Buds&Blooms → **BUDS BLOOMS** (ключ `BUDS AND BLOOMS`, OCR).

## 5. Структура кода

| Файл | Назначение |
|------|-----------|
| `pyparser/readers.py` | чтение pdf/xls/xlsx → `Doc`; OCR-фолбэк для сканов |
| `pyparser/ocr.py` | OCR (rapidocr + pypdfium2), ленивый движок |
| `pyparser/extract.py` | поставщик, сумма (уровнями), дата, валюта |
| `pyparser/aliases.py` | справочники сопоставления и правила пропуска |
| `pyparser/balance.py` | `BalanceWriter`: поиск блока, дозапись, формулы, новый столбец, дубли |
| `pyparser/phase1.py` | таблица распознавания (без записи) |
| `pyparser/phase2.py` | агрегация + запись + отчёт + экспорт очереди (+ автопоиск) |
| `pyparser/review.py` | экспорт/импорт редактируемой очереди |
| `Обработать баланс.bat` | шаг 1 в один клик |
| `Дописать очередь.bat` | шаг 2 в один клик |
| `ИНСТРУКЦИЯ.md` | краткая инструкция для пользователя |

## 6. Проверено

На 3 поставках (06.18 / 06.25 / 07.02): распознавание генерализуется,
на 07.02 — **~88 из 100** файлов записаны автоматически. Идемпотентность
ловит уже внесённые вручную строки (совпадение сумм — подтверждение точности).
Полный цикл «авто-запись → очередь → дозапись» отработан end-to-end.
